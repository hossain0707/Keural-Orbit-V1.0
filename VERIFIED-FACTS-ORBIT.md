# VERIFIED-FACTS — Keural Orbit (Gemma 4 base)

Hands-on verified on this machine 2026-07-22 (meta-device instantiation + peft attach test,
CPU only — GPUs/gateway untouched). This is the ground truth for fine-tuning **Keural Orbit**
from **google/gemma-4-26B-A4B-it**. Same goal as Keural Nova: preserve the base model's
benchmarks everywhere, only improve Korean understanding & response.

## 1. Base model (verified from config.json + installed transformers 5.12.1)

- Repo: `google/gemma-4-26B-A4B-it` — **public, NOT gated, Apache-2.0**. 12 files. dtype bf16.
- Class `Gemma4ForConditionalGeneration`, `model_type: gemma4`. **transformers 5.12.1 supports it**
  (`from transformers import Gemma4ForConditionalGeneration` works).
- **ms-swift 4.4.0 supports it**: registered as `MLLMModelType.gemma4`, model id
  `google/gemma-4-26B-A4B-it`, template `gemma4` (and a `gemma4_nothinking` variant).
- Text: **30 layers, hidden 2816, 26B total / ~4B active**, MoE with **128 experts, top-8**,
  moe_intermediate 704, PLUS a **dense MLP on every layer** (intermediate 2112) — i.e. each
  layer has *both* a dense MLP and a sparse expert block.
- Attention: hybrid **sliding (24 layers) + full (6 layers: 5,11,17,23,29)**; `attention_k_eq_v:
  true` → **full-attention layers have NO separate `v_proj`** (K=V shared); sliding layers do.
- Context: **max_position_embeddings 262,144 (256K)**; extensible via YaRN like Gemma docs.
- Multimodal: **vision tower present** (Image-Text-to-Text). Audio tokens exist in vocab but
  `audio_config: null` → **no audio** (no STT/TTS).
- `tie_word_embeddings: true` → lm_head tied to embed_tokens (do not adapt embeddings).

## 2. Module map (verified on meta device)

- `model.language_model.layers.{i}.self_attn.{q_proj,k_proj,v_proj,o_proj}` — nn.Linear
  (v_proj absent on full-attention layers). Plus q/k/v_norm (RMSNorm, not targeted).
- `model.language_model.layers.{i}.mlp.{gate_proj,up_proj,down_proj}` — dense MLP, nn.Linear.
- `model.language_model.layers.{i}.router.{proj (Linear), scale, per_expert_scale}` — **the
  ROUTER. MUST stay frozen.**
- `model.language_model.layers.{i}.experts.gate_up_proj` [128, 1408, 2816] and
  `...experts.down_proj` [128, 2816, 704] — **fused nn.Parameter tensors** (like Qwen);
  reachable only via peft `target_parameters`.
- `model.vision_tower.*` — vision encoder; its q/k/v/o/gate/up/down_proj are
  **`Gemma4ClippableLinear`** (NOT nn.Linear) wrapping an inner `.linear`. **Freeze entirely.**
- `model.embed_vision.embedding_projection`, `model.language_model.embed_tokens`, `lm_head` —
  frozen.

## 3. Verified LoRA config (peft attach test PASSED, 2026-07-22)

🔴 **A plain `target_modules` list does NOT work** — the vision tower's `q_proj` etc. are
`Gemma4ClippableLinear`, which peft can't wrap → `ValueError: Target module ... not supported`.
**Must scope LoRA to the language model with a regex.** Verified-passing config:

```yaml
target_regex: 'model\.language_model\.layers\.\d+\.(self_attn\.(q_proj|k_proj|v_proj|o_proj)|mlp\.(gate_proj|up_proj|down_proj))'
target_parameters: [gate_up_proj, down_proj]   # fused routed experts (128/layer)
lora_dropout: 0.0    # REQUIRED — peft ParamWrapper crashes with dropout != 0 (same as Qwen)
```

Attach test result (6-layer shrink): experts adapted, LM attention adapted, LM dense MLP
adapted, **0 violations** (vision / router / embed / lm_head all frozen). This targets both the
dense MLP and the 128 routed experts — most of the model's FFN capacity.

## 4. What differs from the Keural Nova (Qwen) pipeline

- **Scoping via `target_regex`, not `target_modules` list** (vision ClippableLinear problem).
- **No linear-attention / Gated-DeltaNet** — Gemma uses sliding vs full attention, same q/k/v/o
  module names; the verify gate's "expected layer sets" logic must change accordingly.
- **No MTP block** (Gemma4 has none) — merge is simpler than Qwen's; BUT **tied embeddings**
  (`tie_word_embeddings: true`) — the merge/save must preserve tying (don't duplicate/split).
- Router module is `router.proj` (+ scale/per_expert_scale), not Qwen's `mlp.gate`.
- Template: ms-swift `gemma4` / `gemma4_nothinking` (not Qwen's qwen3_5).

## 5. Self-contained project (no dependency on the Nova/Qwen pipeline)

This folder is standalone — its own `scripts/`, `configs/`, and `data/` — so it can be
pushed to GitHub on its own. Nothing here imports from `../scripts`.

- **Dataset: `data/processed/`** (the v2 set — 146,274 rows: 50k ko conv, 25k clean code,
  12.5k×2 replay, ~20k math, ~20k MCQ, 5k long-form, 1.5k identity; test-split-clean,
  code-validated, identity-decontaminated). `train.jsonl` is gitignored (>100 MB) and
  regenerated by `scripts/build_dataset.py --out data/processed`; `eval/pilot/manifest`
  are committed.
- **Recipe (per V2-TRAINING-PLAN):** 1 epoch, LR 5e-5, effective batch ~32, bf16, TP=2.
- Scripts were forked from the Nova pipeline and Gemma-adapted: `train.py`/`run_eval.py`/
  `publish.py` are config-driven; **`verify_lora_targets.py` and `merge_lora.py` are
  Gemma-specific** (regex targeting; no MTP; tied embeddings). The merge has a CPU
  `--self-test` that PASSES end-to-end on a tiny Gemma4 fixture (forward equivalence 2e-6).

## 6. Honest goal caveats (unchanged from Nova)

SFT preserves + sharpens; it does **not** add knowledge. Realistic target: **match base on
knowledge/general benchmarks (±noise), improve Korean fluency/format/persona.** Not guaranteed
lossless — must be **measured** (baseline eval vs post-train) before shipping, exactly as with
Nova. Context stays 256K (not 1M unless YaRN enabled). Multimodal present but untrained/untested.
